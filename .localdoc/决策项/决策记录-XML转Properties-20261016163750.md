## 决策列表

### DEC-001: 采用 Qt 6、CMake 和 Qt Quick/QML
- 阶段：方案设计
- 背景：需要初始化 Windows 图形应用，并明确技术栈为 Qt + QML。
- 可选方案：Qt 6 + CMake；Qt 5 + qmake；Qt 6 + qmake。
- 最终选择：Qt 6 + CMake + Qt Quick/QML。
- 选择理由：使用当前 Qt 生态和现代构建方式，便于 Windows 构建及后续维护。
- 影响：构建环境需要 Qt 6 和对应 CMake 工具链。

### DEC-002: 使用树形解析后生成路径键
- 阶段：方案设计
- 背景：需要同时处理嵌套节点、属性和重复兄弟节点。
- 可选方案：流式即时输出；先构建 XML 节点树再递归输出；使用第三方 XML 库。
- 最终选择：使用 Qt `QXmlStreamReader` 构建轻量节点树，再递归生成 properties。
- 选择理由：保留兄弟节点计数所需的上下文，依赖 Qt 自带组件且实现可测试。
- 影响：会暂存 XML 结构，适合配置文件场景，不针对超大 XML 做流式低内存优化。

### DEC-003: 使用点号路径和显式重复节点下标
- 阶段：需求澄清
- 背景：需要定义 XML 到 properties 的稳定键名映射。
- 可选方案：仅使用叶子名称；使用点号路径；使用 XPath 风格路径。
- 最终选择：嵌套节点使用点号路径，属性使用 `.@`，重复同名节点使用 `[n]`。
- 选择理由：可读性高，能避免不同分支出现同名叶子键时互相覆盖。
- 影响：输出键名包含结构信息，重复节点的索引从 0 开始。

### DEC-004: 最低 Qt 版本及文件 URL、CTest 运行环境处理
- 阶段：独立代码审查后的修复
- 背景：`qt_standard_project_setup()` 要求至少 Qt 6.3；QML 文件对话框返回的是文件 URL，手动截取 `file:///` 无法可靠处理 UNC；在未配置 Qt bin 到 PATH 的终端中直接运行 CTest 可能找不到 Qt DLL。
- 可选方案：继续声明 Qt 6.2 并依赖环境；在 QML 中手动转换路径；由 C++ 使用 `QUrl` 解析并在 CTest 中显式注入 Qt DLL 目录；或只要求用户手工配置 PATH。
- 最终选择：将最低 Qt 版本提升为 6.3；QML 将完整文件 URL 交给 C++，C++ 使用 `QUrl::toLocalFile()` 处理本地文件 URL，同时保留普通 Windows 路径和 UNC 路径并拒绝非本地 URL；Windows CTest 命令通过 `cmake -E env` 将 Qt Core DLL 目录加入 PATH。
- 选择理由：遵循 Qt 构建要求，避免 URL 解码和 UNC 主机信息丢失，并让标准 `ctest --test-dir build2 -C Release --output-on-failure` 在干净 PATH 下可执行。
- 影响：项目需要 Qt 6.3 或更高版本；文件接口明确只接受本地路径或 `file://` URL；Windows CTest 使用构建时 Qt 目标目录，不影响其他平台。

### DEC-005: 审查后补充严格解码与 QML/UNC 回归测试
- 阶段：最终代码审查后的修复
- 背景：宽松 UTF-8 解码会静默替换非法字节；文件 URL 分类和 QML 按钮流程需要自动化回归覆盖。
- 最终选择：使用 Qt `QStringDecoder::Utf8` 检测非法输入并返回明确错误；提取本地路径解析函数供测试；增加 `QT_QPA_PLATFORM=offscreen` 的 QML smoke test，并为关键控件设置 `objectName`。
- 影响：非法 UTF-8 文件不再继续转换；QML smoke test 不打开真实文件对话框；UNC 测试只验证 `file://server/share/...` 的分类，不依赖真实网络共享。

### DEC-006: 最终审查修复 QML 资源入口与生命周期及对话框 smoke 覆盖
- 阶段：最终代码审查后的最后修复
- 背景：生产应用通过 `Xml2Prop` QML 模块提供 `qrc:/Xml2Prop/qml/Main.qml`，而 smoke test 曾使用独立的 `Xml2PropSmoke` 资源入口；同时 QML context property 必须在 engine 销毁前保持有效。
- 最终选择：smoke test 使用与生产一致的 `Xml2Prop` URI 和 qrc 路径；`converter` 在 `QQmlApplicationEngine` 前声明；为打开和保存 `FileDialog` 设置 objectName 并在 offscreen smoke test 中验证对象存在。
- 选择理由：测试实际覆盖生产 QML 资源路径，避免独立测试资源掩盖打包问题；局部变量逆序销毁确保 context property 不悬空；不依赖不稳定的真实系统文件对话框交互。
- 影响：测试仍只在 offscreen 下验证对话框对象与核心界面流程；真实 UNC 共享读写继续受环境限制，仅执行 URL 分类测试。

### DEC-007: 最终审查后补充原子保存与可调用 QML 文件处理
- 阶段：最终审查后的修复
- 背景：保存文件不能在写入失败时截断既有目标；QML smoke test 还需要覆盖文件对话框 accepted 的实际处理逻辑，同时不能依赖真实系统对话框。
- 最终选择：保存接口使用 `QSaveFile` 写入并 `commit()` 原子替换；保存对话框设置 `defaultSuffix: "properties"`；将 accepted 处理抽为 `loadXmlFile(fileUrl)` 和 `savePropertiesFile(fileUrl)`，smoke test 通过临时文件的 `QUrl::fromLocalFile()` 经 `QMetaObject` 调用。
- 选择理由：临时文件写入及提交失败不会破坏既有目标；QML 函数调用可直接验证 accepted 处理的成功和错误状态，且不弹出系统对话框。
- 影响：保存错误测试使用稳定的目录目标场景；QML smoke test 继续使用生产 `qrc:/Xml2Prop/qml/Main.qml` 资源入口，真实 UNC 共享读写仍只做路径分类验证。
