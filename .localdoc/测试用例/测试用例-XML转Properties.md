# 测试用例：XML 转 Properties

## 测试范围

覆盖 XML 转 properties 核心规则、错误处理和 UTF-8 文件读写；界面通过构建验证，核心行为通过 Qt Test 自动化验证。

## 用例列表

### TC-001: 嵌套元素转换
- 前置条件：准备包含多层元素的 XML。
- 操作步骤：调用转换核心。
- 预期结果：生成点号路径键和值。
- 优先级：P0

### TC-002: 属性转换
- 前置条件：元素包含一个或多个属性。
- 操作步骤：调用转换核心。
- 预期结果：属性以 `.@属性名` 追加到元素路径。
- 优先级：P0

### TC-003: 重复节点转换
- 前置条件：同一父节点下存在多个同名子节点。
- 操作步骤：调用转换核心。
- 预期结果：重复节点使用从 0 开始的下标。
- 优先级：P0

### TC-004: properties 特殊字符转义
- 前置条件：键和值包含反斜杠、`=`、`:`、制表符、回车、换页和控制字符。
- 操作步骤：调用转换核心。
- 预期结果：输出符合 Java properties 语法的键和值转义。
- 优先级：P1

### TC-005: 非法 XML
- 前置条件：输入未闭合或结构非法的 XML。
- 操作步骤：调用转换核心。
- 预期结果：返回空结果并提供解析错误。
- 优先级：P0

### TC-006: 空叶子节点
- 前置条件：XML 包含无文本的叶子元素。
- 操作步骤：调用转换核心。
- 预期结果：输出 `key=`。
- 优先级：P1

### TC-007: 项目构建与测试
- 前置条件：已安装 Qt 6 和 CMake。
- 操作步骤：执行项目构建和 CTest 命令。
- 预期结果：应用和测试目标构建成功，CTest 全部通过。
- 优先级：P0

### TC-008: 文件 URL 与纯空白节点
- 前置条件：使用 `file://` 本地文件 URL，并准备只包含格式化空白的节点。
- 操作步骤：调用文件读写接口和转换核心；另使用非本地 URL。
- 预期结果：普通路径及本地文件 URL 均可读写，非本地 URL 返回错误，纯空白叶子输出 `key=`。
- 优先级：P1

### TC-009: 生产 QML 入口与文件对话框 smoke test
- 前置条件：在 offscreen 平台构建 QML smoke test。
- 操作步骤：从 `qrc:/Xml2Prop/qml/Main.qml` 加载界面，查找转换、清空、打开和保存控件及两个 `FileDialog` 对象。
- 预期结果：生产应用和 smoke test 使用一致的 QML 资源入口；打开、保存对话框对象均存在，转换、错误和清空流程通过；不打开真实系统文件对话框。
- 优先级：P1

### TC-010: QML 文件载入和保存处理
- 前置条件：在 offscreen 平台加载生产 `qrc:/Xml2Prop/qml/Main.qml` 入口，准备临时 UTF-8 XML 文件。
- 操作步骤：通过 `QMetaObject` 调用 QML 的 `loadXmlFile(QUrl)` 和 `savePropertiesFile(QUrl)` 函数，不打开真实系统文件对话框；再调用载入不存在文件的场景。
- 预期结果：输入编辑器载入 XML，输出保存为 UTF-8 properties，成功状态为非错误；文件不存在时状态栏进入错误状态。
- 优先级：P1

### TC-011: 保存失败的原子性
- 前置条件：准备包含既有哨兵文件的目录路径作为保存目标。
- 操作步骤：将目录路径传给文件保存接口。
- 预期结果：保存失败并提供错误信息，既有目录内容保持不变；正常保存使用 QSaveFile 原子替换。
- 优先级：P0

## 测试命令

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

通用：桌面应用转换核心与本地文件能力。
